# Contributing to EvalHub

Thank you for improving EvalHub.

1. Open an issue for substantial changes before investing in implementation.
2. Keep each change focused and avoid committing generated builds, local data,
   credentials, screenshots, or machine-specific paths.
3. Preserve the visible `EvalHub by YJW` attribution and all license notices.
4. Run `npm run check` before submitting a pull request.
5. Describe the user impact, implementation boundary, tests, and any security or
   compatibility considerations in the pull request.

By contributing, you agree that your contribution is licensed under the
[EvalHub Community License](LICENSE) and that you have the right to submit it.
